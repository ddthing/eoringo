# Google OAuth 신뢰 정보 설계

## 목표

Google 로그인 과정에서 Supabase 프로젝트 도메인이 먼저 보이더라도 사용자가 피싱으로 오해하지 않도록, 에오링고의 정체성·데이터 범위·문의 경로를 앱과 OAuth 동의 화면에서 일관되게 제공한다.

## 범위

1. `/privacy`와 `/terms`에 공개 안내를 제공한다. 두 페이지는 로그인 없이 열리고, 앱의 기존 색·여백·카드 규칙을 따른다.
2. 개인정보 안내에는 다음의 검증 가능한 사실만 적는다.
   - 기본 루틴 데이터와 캐릭터 이미지는 기본적으로 사용자의 브라우저에 저장된다.
   - Google 연결 및 사용자의 동의 뒤에만 Supabase를 통한 기기 간 동기화를 시작한다.
   - Google 로그인은 기본 프로필과 이메일을 요청하며 Google 비밀번호, Gmail, Drive 데이터에는 접근하지 않는다.
3. 로그인 전/게스트 상태의 계정 패널에 간결한 보안 안내와 개인정보 안내 링크를 표시한다.
4. 설정의 앱 정보 카드에서 개인정보 안내와 이용 안내를 항상 찾을 수 있게 한다.
5. Google Auth Platform의 `eoringo-auth` 프로젝트에 다음 브랜드 정보를 설정한다.
   - 앱 이름: `에오링고` (기존 값 유지)
   - 로고: 배포 중인 앱 아이콘
   - 홈페이지: `https://eoringo.pages.dev/`
   - 개인정보처리방침: `https://eoringo.pages.dev/privacy`
   - 서비스 약관: `https://eoringo.pages.dev/terms`
   - 승인된 도메인: `eoringo.pages.dev` 추가, 기존 Supabase 도메인은 유지

## 안전 경계

- OAuth 클라이언트 ID/보안 비밀, 요청 범위, Supabase Auth 설정, RLS 및 사용자 데이터는 변경하지 않는다.
- 별도 비용이 발생할 수 있는 Supabase 커스텀 도메인은 활성화하지 않는다.
- Google OAuth 앱 게시(테스트 중 → 프로덕션)는 접근 대상을 넓히므로 별도 사용자 승인 없이는 실행하지 않는다.
- 법률 자문이나 보관 기간처럼 현재 확인할 수 없는 약속은 안내문에 넣지 않는다.

## 검증

- 정적 렌더 테스트로 두 공개 페이지의 핵심 보안 문구와 상호 링크를 확인한다.
- 계정 패널과 앱 정보 테스트로 신뢰 링크를 확인한다.
- 빌드 후 배포 URL에서 `/privacy`, `/terms`의 직접 진입과 링크 상태를 확인한다.
- Google 브랜딩 저장 후 화면의 로고·홈페이지·정책 링크·도메인을 재확인한다.
