# 공통 시작 기준선과 타이포그래피 계층 설계

## 상태

- 설계 승인: 2026-08-10
- 범위: 오늘·숙제·일정·설정 탭의 첫 콘텐츠 기준선과 앱 전반의 과도한 굵기 사용
- 제외: 인증 관련 사용자 변경, 색상 팔레트와 기능 동작 변경

## 목표

네 개의 하단 탭이 같은 앱의 화면처럼 보이도록 첫 콘텐츠의 시작 기준을 공통화한다. 반응형에서 절대 좌표에 의존하지 않고 `AppShell`의 문서 흐름, 공통 gutter, 토큰 기반 여백을 사용한다. 폰트는 정보 계층에 따라 필요한 곳만 강하게 표시한다.

## 레이아웃 규칙

- 모든 탭의 첫 콘텐츠는 `main`의 공통 흐름에서 시작한다.
- 오늘은 현재 대시보드 카드가 기준점이 된다.
- 숙제·일정·설정은 공통 페이지 헤더 기준으로 아이콘과 제목을 정렬한다.
- 숙제의 sticky 동작은 유지하되, sticky 바깥쪽이 아닌 내부 헤더만 공통 기준선에 맞춘다.
- `top: 76px`, `left: 13px` 같은 화면 좌표 고정은 사용하지 않는다.
- 좁은 폭에서는 flex/grid의 `min-width: 0`, 텍스트 줄바꿈과 기존 safe-area 여백을 유지한다.

## 타이포그래피 규칙

- 800: 페이지 제목, 핵심 캐릭터명·전장명·큰 진행률처럼 시선을 우선해야 하는 값
- 700: 일반 섹션 제목, 버튼, 상태 라벨, 작업 그룹명
- 500~600: 설명, 날짜, 보조 정보, 빈 상태 안내
- 기존 `font-black`은 의미상 핵심이 아닌 라벨·버튼·보조 텍스트에서 낮은 계층으로 교체한다.
- `muted-label`과 sticker는 900 대신 700~800 수준으로 낮춘다.

## 검증 기준

- 320px, 390px, 768px, 1280px에서 네 탭의 첫 기준선이 공통 흐름으로 유지된다.
- 어떤 라우트도 `documentElement.scrollWidth`가 viewport보다 크지 않다.
- 다크 모드와 긴 제목에서 겹침·잘림·가로 넘침이 없다.
- 콘솔 오류가 없다.
- 기존 인증 관련 사용자 변경은 stage/commit 대상에 포함하지 않는다.
- 앱 테스트, 타입 검사, 빌드가 통과한다.
