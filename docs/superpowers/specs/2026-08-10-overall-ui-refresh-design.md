# 에오링고 전체 공통 UI 개선 설계

## 상태

- 설계 승인: 2026-08-10
- 구현 상태: 설계 검토 대기
- 대상: 앱 전체 공통 UI 및 홈·숙제·일정·설정의 시각 표현

## 1. 목표

에오링고의 기존 브랜드와 정보 구조를 유지하면서, 10년차 시니어 디자이너가 검토한 수준의 일관된 UI 위계를 만든다. Material 3의 표면·상태·접근성 원칙과 shadcn 계열의 조합 가능한 공통 컴포넌트 원칙을 참고하되, 현재 제품의 언어와 데이터 흐름에 맞춰 구현한다.

이번 작업의 핵심은 색상과 장식을 늘리는 것이 아니라, 사용자가 현재 위치·상태·다음 행동을 즉시 이해하도록 여백, 타이포그래피, 아이콘, 상태 표현, 모션을 정돈하는 것이다.

## 2. 연속성 가드레일

다음 요소는 변경하지 않는다.

- 하단 네비게이션의 위치·탭 구조·핵심 명칭
- 홈·숙제·일정·설정이라는 핵심 정보 구조
- 설정 화면의 섹션 순서와 카드 중심 레이아웃
- 캐릭터, 숙제, 일정, 설정에 관한 기존 데이터와 사용자 흐름
- Pretendard 기반 한글 타이포그래피와 둥근 카드 중심의 제품 인상
- 현재 테마 색상 선택 기능 및 light/dark 모드 기능

다음 변화는 허용한다.

- 공통 카드·버튼·배지·세그먼트·섹션 헤더의 위계와 상태 스타일 개선
- 카드 내부 여백, 섹션 간 리듬, 반응형 그리드 개선
- Lucide 아이콘의 크기·선 굵기·배치 통일
- 선택·완료·진행·대기·오류 상태를 텍스트와 아이콘을 포함해 명확하게 표현
- 진입·완료·바텀시트·hover/pressed/focus 모션 개선

다음 변화는 하지 않는다.

- 제품을 새 앱처럼 보이게 하는 전면적인 레이아웃 개편
- 영어 중심 편집 디자인 또는 과도한 게임 UI
- 새로운 유료 서비스, API, UI 라이브러리 의존성 추가
- 인증, 동기화, 라우팅, 저장 데이터 동작 변경

## 3. 색상 시스템

### 3.1 기본 비율

- 화면의 80~90%는 중성 배경, 카드, 텍스트로 구성한다.
- 현재 선택한 테마 색상 하나를 제품의 주색으로 사용한다.
- 핑크·라벤더·크림·하늘색은 테마 선택 UI 또는 상태상 필요한 경우에만 사용한다.
- 카드별 장식색을 분산하지 않고, 테두리·여백·그림자·타이포그래피로 계층을 만든다.

### 3.2 의미별 사용

| 역할 | 사용 위치 | 표현 원칙 |
| --- | --- | --- |
| 주색 | 활성 탭, 주요 버튼, 진행률, 완료 체크, 핵심 수치 | 현재 테마 색상 하나만 사용 |
| 성공 | 완료, 동기화 성공 | 낮은 채도 표면 + 아이콘 + 라벨 |
| 정보 | 안내, 동기화 상태 | 낮은 채도 표면 + 정보 아이콘 |
| 경고 | 준비 중, 주의 | 낮은 채도 표면 + 명시적 라벨 |
| 위험 | 삭제, 데이터 초기화 | 위험색 + 동작 설명 + 확인 절차 |

색상만으로 상태를 구분하지 않는다. 상태에는 가능한 경우 아이콘과 텍스트를 함께 제공한다.

## 4. 공통 컴포넌트 설계

### Card

- elevated, outlined, soft 변형의 의미를 명확히 유지한다.
- 기본 카드에는 일관된 모서리, 얇은 outline, 약한 elevation만 적용한다.
- 내부 섹션의 제목·설명·행동 영역을 고정된 여백 토큰으로 정렬한다.
- 긴 한글 텍스트와 긴 버튼 라벨은 줄바꿈되어도 카드 너비를 침범하지 않는다.

### Button / IconButton

- primary, secondary, ghost, destructive 의미를 유지한다.
- 아이콘은 동작을 설명하거나 스캔 속도를 높이는 경우에만 사용한다.
- 모든 버튼은 최소 44px 터치 영역을 보장한다.
- loading, disabled, hover, pressed, focus-visible 상태를 구분한다.

### Badge / StatusMessage

- 상태의 보조 정보로 사용하며, 화면을 색상으로 채우는 장식 요소로 사용하지 않는다.
- 배지에는 가능한 경우 짧은 상태 라벨을 넣는다.
- 성공·정보·경고·위험의 의미가 페이지마다 달라지지 않도록 토큰을 공유한다.

### SegmentedControl

- 서로 배타적인 선택에만 사용한다.
- 현재 선택 상태는 배경·테두리·텍스트 대비로 명확히 표현한다.
- 모바일에서 선택지 텍스트가 카드 밖으로 튀어나오지 않도록 `min-width: 0`, 줄바꿈, 충분한 높이를 보장한다.

### SectionHeader

- 작은 eyebrow, 제목, 설명, 우측 행동의 순서로 통일한다.
- 제목은 정보 위계를 만들고, eyebrow는 탐색 보조 역할만 한다.
- 좁은 화면에서는 행동 영역이 제목을 압박하지 않도록 줄바꿈 규칙을 둔다.

## 5. 화면별 적용

### 앱 셸·하단 네비게이션

- 현재 고정 위치와 탭 수는 유지한다.
- 활성 탭은 주색의 낮은 채도 컨테이너와 아이콘·라벨 대비로 표현한다.
- 비활성 탭은 중성색으로 낮추되, 터치 가능성은 유지한다.
- safe-area inset과 콘텐츠 하단 여백을 함께 보장한다.

### 홈

- 캐릭터·오늘 날짜·일일 진행률을 첫 시선에 묶는다.
- 진행률은 숫자, progress bar 또는 ring, 설명 텍스트를 함께 사용한다.
- 오늘 할 일은 완료 상태와 남은 행동이 즉시 구분되도록 한다.
- 보조 위젯은 중요도가 낮은 순으로 배치하고, 2열 레이아웃은 좁은 화면에서 자동으로 1열 전환한다.

### 숙제

- 목록·그룹·관리 모드의 차이를 헤더와 도구 영역에서 명확히 한다.
- 완료 체크와 카운트 변화에 짧은 피드백을 제공한다.
- 작업 행은 아이콘, 제목, 보조 정보, 액션의 정렬을 유지한다.

### 일정

- 날짜 탐색, 오늘 표시, 이벤트 종류를 한눈에 구분한다.
- 이벤트 색상은 의미가 필요한 경우에만 낮은 채도로 사용한다.
- 달력 셀과 펼침 영역의 등장 모션은 정보 탐색을 방해하지 않는 짧은 시간으로 제한한다.

### 설정

- 기존 섹션 순서와 카드 구조를 유지한다.
- 테마·화면 모드 선택은 카드 간 간격과 내부 여백으로 충분한 호흡을 준다.
- 계정·데이터·앱 정보 영역은 제목, 설명, 행동 버튼의 우선순위를 명확히 한다.
- 긴 설명문과 한국어 제목이 카드 경계를 침범하지 않도록 반응형 규칙을 공통 적용한다.

## 6. 모션 원칙

- 일반 상태 전환은 150~220ms를 기본으로 한다.
- 페이지·섹션 진입은 160~240ms 범위의 짧은 stagger를 사용하되, 콘텐츠가 늦게 나타나는 인상을 주지 않는다.
- 완료 체크는 짧은 pop/scale 피드백을 사용한다.
- 바텀시트·다이얼로그는 220~280ms의 부드러운 진입을 사용한다.
- hover는 데스크톱에서만 적용하고, pressed는 터치에서도 명확해야 한다.
- `prefers-reduced-motion: reduce`에서는 장식 애니메이션과 transform을 제거하거나 즉시 상태 전환으로 대체한다.

## 7. 접근성·반응형 기준

- 버튼, 토글, 입력, 탭의 터치 영역은 44px 이상을 유지한다.
- 모든 키보드 인터랙션 요소에 명확한 `focus-visible` 상태를 제공한다.
- 상태를 색상만으로 전달하지 않는다.
- 제목·설명·버튼의 대비가 유지되도록 light/dark 토큰을 함께 조정한다.
- 모바일 320~390px 폭에서 긴 한글 텍스트, 설정 카드, 하단 네비게이션을 확인한다.
- 태블릿·데스크톱에서는 콘텐츠 최대 폭과 2열 위젯의 균형을 확인한다.
- 가로 스크롤은 의도된 컴포넌트 외에는 발생하지 않아야 한다.

## 8. 구현 순서

1. `src/styles/globals.css`의 토큰·공통 모션·표면 위계 정리
2. `src/components/ui` 공통 컴포넌트 상태와 간격 개선
3. `AppShell`·`BottomNav`의 활성·포커스·safe-area 처리 개선
4. 홈·숙제·일정·설정의 공통 컴포넌트 적용과 레이아웃 정렬
5. 모바일·다크 모드·reduced-motion 시각 검증
6. 기존 테스트·타입 검사·빌드·보안 검사 실행

## 9. 검수 기준

- 기존 기능·라우팅·데이터 흐름에 회귀가 없다.
- 현재 앱의 브랜드와 정보 구조를 알아볼 수 있다.
- 한 화면에 불필요한 색상이 여러 개 동시에 나타나지 않는다.
- 설정 탭 텍스트와 카드가 모든 지원 폭에서 경계를 침범하지 않는다.
- 주요 동작에 아이콘·라벨·상태 피드백이 일관되게 적용된다.
- 모바일에서 주요 동작의 터치 영역이 충분하다.
- 키보드 포커스와 reduced-motion 요구를 만족한다.
- 단위 테스트, 타입 검사, 프로덕션 빌드가 통과한다.
- 브라우저에서 모바일·데스크톱 주요 화면을 실제 렌더링으로 확인한다.
