# 일정·기념일 P0/P1 UX 개선 설계

## 목표

에오링고의 일정 화면에서 게임 일정과 개인 기념일의 우선순위를 명확히 하고, 등록한 기념일을 달력에서 바로 발견할 수 있게 한다. 첫 화면에서는 신규 사용자가 26개 숙제 전체에 압도되지 않고 바로 첫 행동을 시작하도록 한다.

## 범위

### 포함

- 현재 월간 달력의 날짜 셀에 개인 기념일 표시
- 오늘 요약과 월간 달력 사이에 다가오는 기념일 요약 표시
- 기념일 전체 추가·수정·삭제의 단일 진입점 유지: 일정 화면
- 홈 기념일 위젯은 읽기 전용 요약과 일정 화면 이동만 제공
- 홈 오늘 체크의 카테고리별 최초 노출 항목을 1개로 축소
- 일정 화면에서 `게임 일정`과 `내 일정`을 명시적으로 구분
- 기존 기념일 데이터의 의미를 `등록 날짜 기준 D-day`로 명시
- 단위/컴포넌트 회귀 테스트와 배포본 검증

### 제외

- 외부 분석 SDK 또는 사용자 행동 데이터 전송
- SEO/OG 메타데이터 개선
- 전면적인 접근성/브라우저 호환성 리팩터링
- 기존 기념일 데이터의 자동 반복 일정 변환

## 사용자 흐름

1. 사용자는 홈에서 오늘의 핵심 숙제와 다가오는 기념일을 짧게 확인한다.
2. 기념일을 관리하려면 홈의 `일정에서 관리` 링크를 통해 일정 화면으로 이동한다.
3. 일정 화면에서 게임 일정과 내 일정을 구분해 읽는다.
4. 월간 달력의 날짜 셀에서 기념일 점/라벨을 발견하고, 아래 관리 카드에서 추가·수정·삭제한다.

## 데이터 및 상태

- `useDdayStore`의 기존 `eventsByCharacter` 구조를 그대로 사용한다.
- 월간 달력은 현재 월의 날짜별 이벤트를 파생 계산한다.
- 다가오는 요약은 기존 홈과 동일하게 오늘과의 절대 일수 기준으로 최대 3개를 보여준다.
- 날짜 셀은 이번 변경에서 읽기 전용으로 유지한다. 상세 bottom sheet나 월 이동은 추가 범위로 만들지 않는다.
- 기존 이벤트는 자동 수정하지 않는다. 반복 일정이 아니라는 점을 문구로 명확히 한다.

## UI 구성

```text
오늘 요약
다가오는 기념일 (이벤트가 있을 때만)
게임 일정 / 월간 달력
내 일정 / 기념일 관리
하우징 매물
범례
```

달력 셀에는 게임 일정 라벨과 함께 기념일 표시점을 둔다. 홈은 빈 상태에서도 관리 폼을 노출하지 않고 일정 화면으로 안내한다.

## 검증 기준

- 이벤트가 있는 날짜 셀에 기념일 표시가 나타난다.
- 이벤트가 없는 사용자의 기존 빈 상태와 달력 레이아웃이 깨지지 않는다.
- 홈에는 추가/수정 폼이 없고 `일정에서 관리` 링크가 존재한다.
- 달력 관리 카드에서 기존 CRUD가 그대로 동작한다.
- 홈 첫 화면의 각 카테고리는 기본 1개 항목만 노출하고 전체 펼치기는 유지한다.
- 기존 도메인 테스트, 전체 테스트, 타입 검사, 프로덕션 빌드가 통과한다.
- P2 SEO/접근성 변경 파일은 수정하지 않는다.
