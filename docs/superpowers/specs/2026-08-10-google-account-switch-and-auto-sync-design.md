# Google 계정 전환과 자동 동기화 설계

## 목표

- 설정 화면에서 현재 기기만 로그아웃할 수 있게 한다.
- Google 계정 선택창을 통해 다른 계정으로 안전하게 전환할 수 있게 한다.
- 게스트에서 Google을 연결한 경우, 기존 `이 기기의 기존 데이터 이어가기` 버튼을 누르지 않아도 검증된 마이그레이션을 자동 실행한다.
- 새 기기에서 로컬 데이터가 비어 있으면 기존 Google 계정의 원격 데이터를 자동으로 불러온다.
- 기존 계정과 현재 기기에 각각 의미 있는 데이터가 있으면 자동 병합하지 않는다.

## 범위와 제외

포함:

- Supabase `signOut({ scope: "local" })` 기반의 기기 로그아웃
- Google OAuth 계정 선택 강제(`prompt=select_account`)
- 설정 화면의 `다른 Google 계정으로 전환` 및 `로그아웃` 동선
- 게스트 연결과 새 기기 진입 시 자동 동기화 부트스트랩
- 자동 마이그레이션 시 기존 검증·읽기 확인·idempotency 경로 재사용
- 자동 동기화 시도와 마이그레이션 영수증의 사용자 식별

제외:

- 서로 다른 Google 계정의 데이터 자동 병합
- 기존 Supabase 스키마 변경
- 캐릭터 이미지의 지속적인 원격 동기화
- 모든 기기에서의 전역 로그아웃 UI
- 원격 데이터와 로컬 데이터가 모두 있는 경우의 새로운 병합 편집기

## 현재 문제

- Auth client에는 `signOut`과 기존 계정 로그인 보조 로직이 있으나 설정 UI에 노출되지 않는다.
- `signOut()`을 옵션 없이 호출하면 Supabase의 기본 전역 로그아웃 동작이 사용될 수 있다.
- Google 연결 후에도 동기화 동의가 없으면 원격 런타임이 시작되지 않는다.
- 마이그레이션 영수증이 다른 사용자에게 재사용되지 않도록 사용자 ID와 결합되어야 한다.
- 현재 계정 데이터가 있는 경우와 현재 기기 데이터가 있는 경우를 구분하지 않고 자동 처리하면 데이터가 섞일 수 있다.

## 사용자 흐름

### 게스트에서 Google 연결

1. 게스트가 `Google 계정 연결`을 누른다.
2. Google 계정 선택창을 표시한다.
3. 연결이 성공하면 현재 Supabase 사용자 ID를 유지한 영구 계정으로 전환한다.
4. 대상 원격 계정이 비어 있으면 기존 로컬 6개 문서를 검증된 마이그레이션 함수로 자동 이전한다.
5. 서버 응답과 read-back digest가 일치할 때만 동기화 동의를 기록하고 원격 런타임을 시작한다.
6. 이전 실패 시 로컬 데이터는 유지하고 설정 화면에 재시도 가능한 상태를 표시한다.

### 새 기기에서 기존 Google 로그인

1. Google 계정 선택 후 세션을 복원한다.
2. 원격 문서를 읽는다.
3. 현재 기기의 데이터가 기본값 수준이고 원격 문서가 있으면 원격 문서를 자동 hydrate한다.
4. 원격 문서가 없으면 빈 계정으로 동기화를 시작한다.
5. 현재 기기에 의미 있는 데이터가 있으면 자동 덮어쓰기를 하지 않고 기존 수동 데이터 선택 UI를 표시한다.

### 다른 Google 계정으로 전환

1. 사용자가 `다른 Google 계정으로 전환`을 누른다.
2. 현재 기기 세션만 로그아웃한다.
3. `prompt=select_account`로 Google 계정 선택창을 연다.
4. 새 계정의 원격 데이터가 있으면 자동으로 불러온다.
5. 새 계정의 원격 데이터가 비어 있어도 이전 계정의 로컬 데이터를 새 계정으로 자동 업로드하지 않는다. 이 경우 명시적인 데이터 선택 UI를 유지한다.

## 모듈 설계

### Auth client/provider

- `signOut(scope = "local")`을 기본으로 한다.
- Google 로그인/연결 함수에 계정 선택 옵션을 전달한다.
- Provider가 `signOut`과 `signInExistingGoogle`을 UI에 제공한다.
- 로그아웃 중 상태를 별도 busy 상태로 표시한다.

### 자동 동기화 부트스트랩

- 기존 `LocalMigrationLauncher`와 `runLocalMigration`을 재사용한다.
- 자동 이전은 대상 계정이 비어 있을 때만 수행한다.
- 자동 이전은 로컬 데이터를 삭제하지 않으며, 검증 완료 전에는 consent receipt를 기록하지 않는다.
- 자동 이전이 아닌 원격 hydrate는 기본 로컬 상태에서만 자동 수행한다.
- 계정 전환 플래그가 있으면 빈 원격 계정에 대한 자동 로컬 업로드를 차단한다.

### 영수증과 경계

- migration receipt에 대상 `userId`를 기록한다.
- receipt는 현재 사용자 ID와 일치할 때만 동기화 동의를 재사용한다.
- 기존 receipt에 사용자 ID가 없으면 자동 완료로 간주하지 않는다.
- 자동 시도는 사용자 ID별로 중복 실행되지 않도록 bounded marker를 둔다.

## 오류와 안전성

- Supabase `destination_not_empty`는 자동 병합하지 않고 수동 선택 상태로 전환한다.
- OAuth 취소 시 기존 세션과 로컬 데이터는 유지한다.
- 로그아웃 실패 시 세션 상태를 임의로 바꾸지 않고 오류를 표시한다.
- 원격 read-back 또는 digest 검증 실패 시 consent를 부여하지 않는다.
- 계정 전환 후 새 계정의 빈 원격 저장소에 이전 계정 로컬 데이터를 자동 전송하지 않는다.

## UI 문구

- 연결 상태: `Google 계정 연결됨`
- 자동 동기화 완료: `이 기기의 데이터가 계정과 자동으로 동기화되었습니다.`
- 수동 선택 필요: `현재 기기와 계정에 데이터가 모두 있어 자동으로 합치지 않았습니다.`
- 전환: `다른 Google 계정으로 전환`
- 로그아웃: `이 기기에서 로그아웃`
- 설명: `로그아웃해도 계정 데이터는 삭제되지 않습니다.`

## 검증 기준

- local scope 로그아웃만 호출되고 global scope는 호출되지 않는다.
- 계정 전환 시 Google 선택창 옵션이 전달된다.
- 게스트 연결 + 빈 원격 계정은 수동 버튼 없이 자동 마이그레이션된다.
- 기존 원격 계정은 기본 로컬 상태에서 자동 hydrate된다.
- 의미 있는 로컬 데이터와 원격 데이터가 모두 있으면 자동 병합하지 않는다.
- 다른 사용자 ID의 receipt가 동기화 동의를 부여하지 않는다.
- OAuth 취소·마이그레이션 실패·read-back 불일치에서 로컬 데이터가 유지된다.
