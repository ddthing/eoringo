# 월간 캘린더 항목 구분 강화 설계

## 상태

- 설계 승인: 2026-08-10
- 범위: 전장 월간·하우징 월간의 날짜 셀과 범례
- 제외: 왼쪽 3px 컬러 라인

## 목표

월간 캘린더에서 `봉바`, `쇄빙`, `온살`, `워코`, `제압`과 하우징의 `신청`, `발표`를 한눈에 구분한다. 전체 앱의 깔끔한 중성 UI는 유지하고, 분류가 필요한 월간 캘린더 영역에서만 제한적으로 저채도 색상을 사용한다.

## 시각 규칙

- 각 전장 종류는 서로 다른 저채도 배경색·테두리·텍스트 색상 조합을 가진다.
- 신청 기간과 발표 기간도 서로 다른 저채도 색상으로 구분한다.
- 왼쪽 컬러 라인, 강한 그라디언트, 과도한 그림자는 사용하지 않는다.
- 날짜 숫자와 짧은 이름은 항상 읽기 쉬운 대비를 유지한다.
- 오늘 날짜는 기존의 주색 테두리·ring을 유지해 분류 색상보다 우선 강조한다.
- 색상만으로 의미가 완성되지 않도록 셀 안에 `봉바`, `신청` 같은 텍스트 라벨을 유지한다.

## 범례

- 기존 범례 접기/펼치기 동작을 유지한다.
- 전장 월간에서는 전장 5종의 짧은 이름과 전체 이름을 보여준다.
- 하우징 월간에서는 신청·발표의 의미를 보여준다.
- 범례의 칩은 해당 월간 셀과 동일한 색상 토큰을 사용한다.

## 구현 범위

- `src/styles/globals.css`: 전장·하우징 캘린더 톤 토큰을 저채도 색상 조합으로 정의한다.
- `src/components/calendar/CalendarPage.tsx`: 현재 월간 모드에 맞는 범례 항목과 접근 가능한 설명을 제공한다.
- 기존 날짜 계산, 로테이션, 하우징 상태, 오늘 강조, 범례 토글 동작은 변경하지 않는다.

## 반응형·접근성

- 390px 폭에서도 셀 내부 텍스트가 잘리지 않거나 가로로 넘치지 않아야 한다.
- 320px, 390px, 768px, 1280px 폭에서 주요 라우트의 문서·본문 가로 폭이 뷰포트를 넘지 않아야 한다.
- 공통 표면은 `--shape-*` 라운드 토큰과 `--elevation-*` 그림자 토큰을 사용하고, 임의 그림자 값으로 시각적 무게를 만들지 않는다.
- 캘린더 셀과 범례 칩은 `min-width: 0`과 내부 잘림 규칙을 가져 좁은 화면에서 레이아웃을 밀어내지 않아야 한다.
- 다크 모드에서 각 색상 조합의 대비를 별도로 제공한다.
- 색상 외에 짧은 텍스트 라벨을 계속 노출한다.
- 기존 hover, focus-visible, reduced-motion 규칙을 유지한다.

## 검수 기준

- 전장 5종이 실제 화면에서 서로 다른 색상 조합으로 보인다.
- 신청·발표가 실제 화면에서 서로 다른 색상 조합으로 보인다.
- 왼쪽 3px 컬러 라인이 존재하지 않는다.
- 오늘 날짜 강조가 유지된다.
- 모바일·데스크톱·다크 모드에서 가로 넘침이 없다.
- 공통 표면의 라운드와 그림자 농도가 동일한 토큰 계열로 계산된다.
- 단위 테스트, 타입 검사, 프로덕션 빌드가 통과한다.
