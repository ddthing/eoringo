# 애드센스 콘텐츠 품질 점검 및 운영 권고안

최종 검토일: 2026-08-23

이 문서는 Google 애드센스에서 표시된 “가치가 별로 없는 콘텐츠” 피드백을 프로젝트 구조와 대조해 기록한 운영 문서입니다. 정책 문구를 반복해 넣는 문서가 아니라, 어떤 화면을 공개 콘텐츠로 보고 어떻게 유지할지 정의합니다.

## 공식 기준 요약

Google의 공식 안내에서 확인한 핵심은 다음과 같습니다.

- 사이트에는 Google이 주제를 파악할 수 있을 만큼의 고유하고 가치 있는 콘텐츠가 있어야 합니다.
- 다른 사이트의 콘텐츠를 부가 가치 없이 복사·삽입하거나, 여러 페이지에 거의 같은 내용을 반복하면 안 됩니다.
- 사용자가 원하는 정보를 찾기 쉬운 탐색 구조와 읽기 쉬운 화면을 제공해야 합니다.
- 게시자 콘텐츠가 없거나 가치가 적은 화면, 미완성 화면, 알림·탐색·행동이 주목적인 화면에는 Google 게재 광고를 두면 안 됩니다.
- 개인정보 처리, Google 제품으로 인한 쿠키·데이터 사용, ads.txt 등의 공개 정보는 정확하고 누락 없이 관리해야 합니다.

## 이번 점검에서 확인한 위험

### 1. 앱 화면과 공개 콘텐츠가 섞여 있었다

운영 페이지의 `/`, `/tasks`, `/calendar`, `/settings`는 실제로는 잘 작동하는 도구지만, 방문자가 읽는 독립 문서가 아니라 체크·탐색·설정 행동을 위한 화면입니다. 로그아웃 또는 신규 방문 상태에서는 진행률과 개인 기록이 비어 있어 검색 방문자에게 제공되는 설명이 제한적이었습니다.

### 2. 공개적으로 읽을 수 있는 독창적 문서가 부족했다

공개 경로에는 개인정보 안내와 서비스 이용 안내가 있었지만, 제품의 핵심 가치인 “파이널판타지14 루틴을 어떻게 정리하는가”를 설명하는 원문이 없었습니다. 앱 기능을 나열하는 것만으로는 사용자가 다시 방문할 이유와 검색 의도를 충분히 충족하기 어렵습니다.

### 3. SPA의 검색 신호가 기본 HTML에 부족했다

초기 HTML은 앱의 공통 title·description만 제공하고, 경로별 canonical·Open Graph·구조화 데이터·사이트맵이 없었습니다. 브라우저에서 렌더링되는 화면과 크롤러가 처음 받는 문서의 차이를 줄이기 위해 경로별 메타데이터와 no-JavaScript 안내를 보완했습니다.

## 적용한 보완

### 공개 콘텐츠

다음 공개 문서를 운영팀의 검토일과 함께 제공합니다.

- `/guide`: 에오링고가 어떤 문제를 해결하고 어떤 기준으로 루틴을 설계하는지 설명하는 허브
- `/guide/routine`: 고정 일일·KST 기준 시각·18시간 주기·주간 경계를 실제 앱 모델과 연결한 문서
- `/guide/getting-started`: 캐릭터 설정, 항목 숨김, JSON 백업, 선택적 Google 연결을 설명하는 시작 안내
- `/guide/calendar`: KST, 전장·하우징·개인 일정의 구분, 커뮤니티 원본 데이터의 한계를 설명하는 문서
- `/guide/task-catalog`: 기본 숙제 항목의 리셋·횟수·캐릭터 범위와 수정 기준을 실제 앱 모델에 맞춰 공개하는 기준표
- `/about`: 제작 목적, 에오링고가 직접 계산하는 것과 외부 원본을 다시 확인해야 하는 것, 편집·오류 제보 원칙
- `/demo`: 로그인 없이 샘플 루틴을 체크해 볼 수 있는 체험 화면. 실제 사용자 콘텐츠가 아니므로 `noindex,nofollow`

각 문서는 서로 연결되고, 앱으로 이동하는 링크·개인정보 안내·서비스 이용 안내·문의 링크를 제공합니다. 하우징 정보처럼 외부 데이터에 의존하는 내용은 정보 제공자와 원본 시트를 노출하며, 게임 내 확인이 필요하다는 한계를 함께 표시합니다. Vite 빌드 후 공개 경로별 정적 HTML을 생성해 JavaScript를 실행하지 않아도 본문·제목·canonical·robots를 확인할 수 있습니다.

### 검색 경로 분리

- 공개 가이드·법적 안내: `index,follow`
- 개인 기록과 행동 중심인 `/`, `/tasks`, `/tasks/manage`, `/calendar`, `/settings`, `/auth/*`: `noindex,nofollow`
- `public/sitemap.xml`: 공개 가이드와 법적 안내만 등록
- `public/robots.txt`: 사이트맵 위치와 민감한 인증·상세 관리 경로를 안내
- 공통 메타: description, robots, canonical, Open Graph, 한국어 locale
- 가이드 문서: Article 또는 CollectionPage JSON-LD, 작성 주체, 발행·수정일
- 체험 화면: 샘플 상호작용만 제공하며 검색·광고 대상에서 제외

`noindex`는 콘텐츠를 숨기기 위한 우회가 아니라, 광고·검색에 적합하지 않은 개인 작업 화면을 공개 편집 문서와 구분하기 위한 것입니다.

### 광고 운영 원칙

현재 앱에는 광고 코드를 추가하지 않았습니다. 광고를 재도입할 때는 다음을 지킵니다.

1. 가이드 본문이 먼저 이해되어야 하며 광고가 콘텐츠보다 많아지지 않아야 합니다.
2. 체크박스, 드롭다운, 달력 셀, 로그인·백업 버튼과 광고가 인접하지 않아야 합니다.
3. 광고를 클릭하지 않으면 화면을 나갈 수 없는 오버레이를 사용하지 않습니다.
4. 사용자의 개인 루틴·인증 상태를 광고 개인 최적화 목적으로 전송하지 않습니다.
5. 광고를 넣기 전에 개인정보 처리방침과 Google 동의 요구사항을 다시 검토합니다.

현재 저장소에는 Google 광고 태그를 넣지 않았습니다. `ads.txt`는 광고 판매자 선언 파일일 뿐 광고 태그나 콘텐츠 품질을 대신하지 않으므로, 실제 광고 재개 시에는 공개 콘텐츠 페이지·개인정보·지역별 동의 설계를 별도로 검증합니다.

정적 파일이 저장소에만 있고 실제 배포에서 빠지는 회귀를 막기 위해 빌드 후 다음 검사를 실행합니다.

```bash
pnpm run verify:public-assets
```

운영 호스트가 기본 `eoringo.pages.dev`가 아니라면 AdSense에 등록한 호스트를 직접 검사합니다.

```bash
PUBLIC_SITE_ORIGIN=https://example.com pnpm run verify:public-deployment
```

PowerShell에서는 `$env:PUBLIC_SITE_ORIGIN = "https://example.com"` 설정 후 같은 명령을 실행합니다. AdSense에 등록한 프로토콜·호스트와 검사 URL이 다르면, `eoringo.pages.dev/ads.txt`가 정상이어도 AdSense 경고가 해소되지 않습니다.

## 재신청 전 체크리스트

- [ ] 운영 주소에서 `/guide`, 네 개의 하위 가이드, `/about`이 새 탭·모바일에서도 열리는가
- [ ] 공개 URL을 JavaScript 없이 요청해도 정적 본문·제목·canonical·robots가 존재하는가
- [ ] `/demo`가 샘플 화면임을 밝히고 사이트맵에 포함되지 않는가
- [ ] 각 공개 문서에 제목, 설명, 검토일, 작성 주체, 내부 링크가 있는가
- [ ] 출처가 필요한 일정 정보에 원본 링크와 최신성 한계가 표시되는가
- [ ] `/sitemap.xml`이 공개 문서만 포함하는가
- [ ] `/robots.txt`가 사이트맵을 가리키는가
- [ ] 앱 행동 화면에 광고를 넣지 않았거나, 넣었다면 게시자 콘텐츠보다 광고가 많지 않은가
- [ ] 개인정보 안내가 실제 저장·동기화 동작과 일치하는가
- [ ] 개인정보 안내가 향후 AdSense 쿠키·웹 비콘·IP·제3자 처리 고지와 지역별 동의 검토 시점을 명확히 구분하는가
- [ ] Search Console에서 사이트맵을 제출하고 공개 문서의 URL 검사를 요청했는가
- [ ] 공개 문서가 실제 검색에 반영된 뒤 애드센스에서 재검토를 요청했는가

코드 변경과 문서 보완은 승인 가능성을 높이는 조치이지만, 애드센스 승인 자체를 보장하지 않습니다. 재신청 전에는 위 체크리스트와 실제 Google 제품 화면의 최신 상태를 다시 확인합니다.
