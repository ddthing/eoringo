# 성능·보안 검수 기록 (2026-09-17)

## 반영한 변경

- 캐릭터 선택·편집 화면을 열 때만 불러오도록 분리. 첫 진입 JS 청크가 401.50KB → 380.11KB, gzip 126.64KB → 121.02KB로 감소했다. 이는 청크 크기 비교이며 실제 방문자의 로딩 시간 측정값은 아니다.
- 외부 Google Fonts/JSDelivr 스타일시트 의존성을 제거했다. Pretendard 1.3.9의 공식 가변 글꼴 서브셋 92개를 라이선스와 함께 자체 제공한다. 브라우저는 unicode-range에 따라 필요한 묶음만 요청한다.
- CSP의 외부 스타일·글꼴 허용 도메인을 제거하고, 해시가 포함된 정적 자산의 장기 캐시와 서비스 워커 재검증 정책을 추가했다.
- 백업은 읽기 전에 64MiB로 제한한다. 이미지 인코딩 데이터 합계는 48MiB, JSON은 깊이·노드 수·문자열 크기를 제한하며 중첩된 예약 키를 거부한다. 정상적인 null 값과 기존 백업 버전은 유지한다.
- 백업 사진을 fetch(data:) 대신 로컬에서 디코딩한다. 운영 connect-src 정책에 의해 사진 복원이 실패할 수 있던 경로를 제거했다. 네트워크가 차단된 상황에서도 복원되는 회귀 테스트를 추가했다.
- Browserslist, baseline-browser-mapping, Vitest 관련 취약점을 패치했다. 전체 워크스페이스 npm 감사 결과 알려진 취약점 0건.
- 모바일 상단 요약을 두 열로 압축하고, 카드 그림자·글자 굵기·데스크톱 최대 폭을 정리했다. 주요 안내 문구를 줄이고, 분 단위로 갱신되는 타이머에서 초 표시를 제거했다.
- 일시적인 화면 오류에 데이터 초기화를 권하던 안내를 새로고침 안내로 바꿨다.

## 검증

- `pnpm run check`: 앱 401개, 보조 도구 22개 테스트 통과. 환경 조건이 필요한 테스트는 각각 1개씩 건너뜀. 타입 검사, 보조 도구 빌드, 비밀정보 검사, 무료 기능 검사, 제품 빌드, 공개 자산 검사 통과.
- `pnpm audit --audit-level low`: 알려진 취약점 없음.
- 1440px 데스크톱, 390px 모바일, 320px 소형 화면 확인. 320px에서 document scrollWidth 310px / innerWidth 320px로 가로 넘침 없음.
- 브라우저에서 숙제 체크·진행률 갱신·체크 복구, 캐릭터 선택창 지연 로딩·Escape 닫기·포커스 복귀, 다크 모드 확인.
- 기존 서버 코드의 JWT 검증 경로와 RLS 마이그레이션을 정적으로 확인했다. 운영 DB 정책 적용 상태와 실계정 동기화·푸시는 이 로컬 환경에서 검증하지 않았다.

## 범위

로컬 코드와 빌드 산출물에 반영했고 운영 배포 후 공개 엔드포인트와 응답 헤더를 확인했다. 실기기 Core Web Vitals 측정과 운영 DB 침투 검사는 수행하지 않았다.

## 추가 개선 및 검증

- 화면 전환, 메모 편집, 확인창, 진행률에 짧은 상태 전환 효과를 적용했다. 진행률은 width 대신 transform으로 움직이며, 동작 줄이기 설정에서는 애니메이션과 전환을 끈다. 별도 애니메이션 라이브러리는 추가하지 않았다.
- 캐릭터 선택창과 확인창을 document.body 포털로 옮겼다. 카드의 transform/overflow에 갇히지 않고, 열려 있는 동안 앱 본문을 inert로 처리한다. 타이머 해제와 포커스 복귀도 보강했다.
- 캐릭터마다 메모 편집 상태를 분리해 다른 캐릭터에 이전 초안을 저장하는 문제를 수정했다.
- 백업 구조 검증 후 복원 확인창을 띄우며, 취소하면 저장하지 않는다.
- 잘못된 푸시 payload(null, 배열, 원시값)를 안전한 기본 알림으로 처리하고 문자열 길이를 제한한다. 외부 URL과 javascript: URL을 열지 않는 회귀 테스트를 추가했다.
- 탭 복귀 시 시계를 즉시 갱신한다. 백그라운드 알림 동작을 유지하기 위해 기존 타이머를 중단하지 않고, 복귀 시 한 개의 타이머로 재정렬한다.
- 경로 오류 화면을 추가해 사용자 화면에 내부 오류 상세를 노출하지 않도록 했다. 숙제 기간 선택 상태를 aria-pressed로 전달하고, 페이지 전환 대기 상태를 표시한다.
- 최종 `pnpm run check`: 앱 410개 + 보조 도구 22개 통과, 조건부 테스트 2개 건너뜀. 타입 검사, 빌드, 공개 자산 검사, 비밀정보 검사 통과.
- 분리된 빌드 미리보기(4174 포트)에서 캐릭터 전환 중 초안 격리, 복원 확인 후 취소, 초기화 확인 후 취소, 배경 입력 차단과 포커스 복귀를 확인했다. 이 과정에서 수집된 브라우저 error 로그는 없었다. 잘못된 주소에서 안내 화면과 홈 복귀도 확인했다.
- 최종 첫 진입 JS 청크는 382.97KB(gzip 121.92KB). 첫 검수 전 401.50KB(gzip 126.64KB) 대비 감소한 상태를 유지한다.

## 저장 안정성 추가 검수

- 이미지 저장은 개별 요청 성공이 아니라 IndexedDB 트랜잭션 완료 후 성공으로 처리한다. 요청 성공 직후 트랜잭션이 취소되는 경우를 재현하고, 실패가 정상적으로 전달되도록 수정했다.
- 전체 사진 백업의 키와 Blob을 하나의 읽기 트랜잭션에서 조회해, 조회 사이 변경으로 사진과 캐릭터가 잘못 연결되는 경로를 제거했다.
- 저장된 기록을 읽거나 JSON으로 해석하지 못하면 백업을 중단하고 안내한다. 오류를 빈 데이터로 바꿔 불완전한 백업을 만들던 처리를 제거했다.
- 새 회귀 테스트는 수정 전 4개 실패를 확인한 뒤 수정 후 통과했다. 최종 `pnpm run check`는 앱 414개와 보조 도구 22개, 총 436개 통과(조건부 2개 건너뜀). 타입 검사, 제품 빌드, 공개 자산 검사, 소스 및 빌드 비밀정보 검사도 통과했다.
- 최신 첫 진입 JS 청크는 382.91KB(gzip 121.95KB). 이번 저장 계층 변경은 이벤트 순서를 제어한 자동 테스트로 검증했으며, 실제 디스크 고장 상황을 브라우저에서 재현한 결과는 아니다.

## 복원 메모리 및 업로드 추가 개선

- 사진 복원 시 기존 사진 전체를 메모리에 읽고 실패 후 다시 쓰던 중복 처리를 제거했다. 원자적 트랜잭션이 기존 사진을 유지하므로 별도 스냅샷이 필요하지 않다. 오래된 스냅샷으로 다른 탭의 변경을 덮어쓸 가능성도 줄였다.
- 전체 사진 삭제 요청을 큐에 넣은 뒤 새 사진 쓰기가 동기적으로 실패하는 경우에도 트랜잭션을 취소하는 테스트를 추가했다.
- 사진 편집기를 열기 전에 파일 크기를 20MiB로 제한했다. 저장 오류는 내부 오류 문자열 대신 간결한 안내로 표시하고, 보조 기술에 오류를 알리도록 했다. 압축된 파일 크기 제한이며 디코딩 후 픽셀 메모리 제한은 아니다.
- `pnpm run check` 전체 통과(436개 테스트, 조건부 2개 건너뜀). 이후 추가한 트랜잭션 취소 테스트를 포함해 저장·복원 관련 18개 테스트도 통과했다. 이번 변경의 업로드 안내는 빌드로 검증했으며 별도 브라우저 조작 검증은 수행하지 않았다.

## 업로드·버튼·실측 추가 검수

- 캐릭터 사진 입력은 JPG·PNG·WEBP·GIF만 허용한다. SVG 등 브라우저 동작 범위가 넓은 형식은 차단하고, 압축 파일은 20MiB, 디코딩 해상도는 2,500만 픽셀로 제한했다.
- 백업 내보내기는 사진을 한 번에 병렬 변환하지 않고 순차 처리한다. 사진 50개, 단일 20MiB, 전체 인코딩 48MiB 한도를 적용해 base64 변환 중 메모리 급증을 막는다.
- 프로필 이미지가 로드되지 않으면 생성한 객체 URL을 즉시 해제해, 화면에 남아 있는 동안 불필요한 Blob 메모리를 보유하지 않는다.
- 로딩 버튼은 원래 콘텐츠의 레이아웃 폭을 유지하고 스피너만 겹쳐 표시한다. `aria-busy`와 로딩 라벨도 함께 전달한다.
- 실측: 프로덕션 미리보기 모바일 성능 추적에서 LCP 164ms, CLS 0.00. 렌더 차단 리소스의 예상 절감은 0ms였다. Lighthouse 모바일은 접근성 100, 모범 사례 100을 기록했고, 최신 재검사에서도 콘솔 오류가 없었다.
- Lighthouse의 SEO 66점은 앱 셸에 설정한 `noindex,nofollow` 정책과 `llms.txt` 부재에서 발생한다. 공개 가이드 페이지의 검색 노출 정책과 충돌하지 않도록 앱 셸 noindex는 유지했다.
- 최종 `pnpm run check`에서 앱 테스트 420개와 보조 도구 테스트 22개가 통과했고, 조건부 테스트 2개를 건너뛰었다. 타입 검사, 빌드, 공개 자산 검사, 비밀정보 검사, 무료 기능 검사도 통과했다. `pnpm audit --audit-level low`에서 알려진 취약점은 없었다.

## 프로필 편집 및 확인창 추가 검수

- 설정 화면에서 실제 파일을 선택해 사진 위치 조정 → 저장 → 캐릭터 저장까지 재현했고, 프로필 이미지가 목록에 반영되는 것을 확인했다. 테스트로 사용한 파일은 이후 삭제하고 원래 캐릭터 상태로 되돌렸다.
- 삭제 확인창은 모바일 하단 정렬을 제거하고 모든 화면 크기에서 중앙에 배치했다. 배경 입력 차단과 포커스 복귀는 기존 동작을 유지한다.
- 최종 `pnpm run check`: 앱 420개 + 보조 도구 22개 테스트 통과, 조건부 테스트 2개 건너뜀. 빌드 및 비밀정보 검사 통과.

## 화면별 접근성 추가 검수

- 숙제 관리와 상세 관리의 검색·수주권 입력에 명시적인 `id`와 `name`을 부여해 브라우저 폼 진단 경고를 제거했다.
- 상세 관리 보조 설명문의 투명도를 제거해 텍스트 대비를 WCAG AA 기준 이상으로 맞췄다. 수정 전 Lighthouse 대비는 3.69:1이었고, 수정 후 모바일 접근성 점수는 100점이다.
- 홈·숙제·상세 관리·일정·설정 및 공개 페이지를 프로덕션 미리보기에서 순회하며 콘솔 오류가 없음을 확인했다.
- 다크 모드 모바일 조건에서도 상세 관리 화면의 Lighthouse 접근성 100, 모범 사례 100을 확인했다.
- 변경 후 `pnpm run check` 전체 통과: 앱 테스트 420개, 보조 도구 테스트 22개, 조건부 테스트 2개 건너뜀. 빌드·비밀정보·무료 기능·공개 자산 검사도 통과했다.

## 운영 배포 추가 검증

- `main` 변경을 GitHub에 push한 뒤 Cloudflare Pages 운영 주소 `https://eoringo.pages.dev`에서 새 해시 자산과 자체 글꼴 응답을 확인했다.
- 홈·숙제·상세 관리·일정·설정 경로가 모두 200으로 응답했고, 브라우저 콘솔 오류가 없었다.
- 운영 응답에서 CSP, HSTS, Referrer-Policy, X-Content-Type-Options, X-Frame-Options, Permissions-Policy가 적용된 것을 확인했다.
- `pnpm run verify:public-deployment`가 운영 주소에서 통과했다. 이 검증은 공개 정적 자산과 응답 상태를 확인하며, 운영 DB·인증 계정·실기기 알림은 포함하지 않는다.

## 초기 로딩 추가 최적화

- 테마 부트스트랩을 별도 요청에서 CSP 해시가 적용된 인라인 스크립트로 옮겨 초기 렌더 차단 요청을 하나 줄였다. 이전 HTML 캐시와의 호환을 위해 같은 동작의 정적 파일은 남겨 두되 새 템플릿에서는 참조하지 않는다. `script-src`에는 계산된 SHA-256 해시만 추가했고 `unsafe-inline`은 허용하지 않았다. 소스 HTML과 헤더의 해시가 일치하는 회귀 테스트를 추가했다.
- 인증 초기화는 첫 페인트 뒤 다음 프레임에서 시작하도록 예약하고, 백그라운드 탭에서는 3초 안전 제한을 둔다. Supabase SDK 청크가 첫 화면을 막지 않으면서 기존 세션 복원과 동기화 동작은 유지된다.
- 운영 주소의 Fast 3G·CPU 4배 모바일 추적에서 LCP가 1.98초에서 1.48초로 감소했다. 최신 배포에서 재측정한 LCP는 1.57초, CLS는 0.00이었고, Supabase SDK 요청은 첫 콘텐츠 페인트 이후로 이동했다. 측정값은 실사용자 데이터가 아닌 합성 환경 수치다.
- 최신 변경 후 `pnpm run check` 전체 통과: 앱 테스트 420개, 보조 도구 테스트 22개, 조건부 테스트 2개 건너뜀. 빌드·비밀정보·무료 기능·공개 자산 검사를 통과했고, 운영 CSP 위반 콘솔 메시지는 없었다.
